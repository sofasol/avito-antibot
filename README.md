# Antibot: поиск ботов по кукам

Тестовое задание Avito Bootcamp. Для каждой `cookie_id` в суточном окне нужно выдать `score` от 0 до 1 - насколько вероятно, что это трафик сервиса автоматизированного сбора данных.
Метрика - Precision при Recall ≥ 0,70, по кукам.

По истории событий каждой куки строятся признаки, дальше их смотрит CatBoost и выдаёт вероятность, что кука - бот.

## Запуск

```bash
cd avito-antibot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
mkdir data  # создать папку и положить в неё train.csv, test.csv, events.csv.gz
```

Дальше запустить `notebooks/03_solution.ipynb` - он пишет `outputs/submission.csv`.

## Подход

Решение сделано в трёх ноутбуках:

1. `01_eda.ipynb` - разведка: чистка данных, поиск ловушек (утечка событий после окна, `captcha_shown`), сравнение поведения ботов и людей по доступным сигналам.
2. `02_experiments.ipynb` - признаки по кукам, проверка LightGBM и CatBoost по времени, разбор мобильных ботов (там ловится хуже всего), перебор идей, выбор итоговой модели.
3. `03_solution.ipynb` - итоговое решение


## Модель и почему она

Выбран CatBoost (глубина 6; 500 деревьев; шаг обучения 0.03; `l2_leaf_reg=3`) поверх набора из 71 признака. В экспериментах он стабильно обгонял LightGBM на итоговом наборе признаков (P@R0.7 0.789 против 0.726, на всех трёх временных блоках проверки) и не уступал ему на базовых признаках.

Финальный score - среднее вероятностей пяти моделей CatBoost с разными сидами.

Пробовала отдельные модели для web и мобильных кук (предсказания потом объединялись) - результат вышел хуже одной общей модели: мобильных ботов слишком мало (311 из 5 174 мобильных кук в train), чтобы учить их отдельно.

## Признаки

71 признак на куку реализован в `features.py`: объём и типы событий, тайминг, поиск, разнообразие просмотров, курсор, платформа и UA, возраст куки, популярность объявлений.

Самых сильных два: на web разброс положения курсора по X почти в одиночку разделяет ботов и людей (AUC 0,94) - у людей курсор гуляет по всему экрану, у ботов сосредоточен и сдвинут влево. На мобильных, где курсора нет и поиск слабый сигнал, лучше всего работает популярность объявлений - сколько ещё кук недавно смотрели то же самое объявление; подняла AUC на мобильных с 0,83 до 0,86. Из неожиданного: ожидалось, что у ботов паузы между действиями ровнее, а вышло наоборот - они двигаются рывками, разброс пауз у них даже больше, чем у людей.

Часть идей в финальный набор не вошла: доли категорий и городов, число сессий и длительность активности либо не дали прироста, либо ухудшили метрику (разобрано в `01_eda.ipynb`).

## Валидация

Проверка идёт по времени, а не случайным разбиением - реальная задача такая же: обучиться на прошлых днях и предсказать следующие (test идёт после train, 20-26.04 против 06-19.04). Обучение и проверка внутри train тоже сдвигались вперёд по дням, несколькими блоками подряд, чтобы оценка не зависела от одного случайного среза.

## Результаты

| | P@R0.7 |
|---|---|
| константа (всем одна метка) | ≈ 0,08 |
| baseline из quickstart (RF на 2 признаках) | ≈ 0,10 |
| базовые 32 признака (CatBoost) | ≈ 0,67 |
| итоговый набор, 71 признак (CatBoost) | ≈ 0,79 |
| проверка на отложенных днях в `03_solution.ipynb` | ≈ 0,81-0,82 |

Оценка на платформе: Precision@Recall>=0.70 = 0.80597

## Ограничения

- Данных о ботах немного (899 из 11 091 в train), оценки по блокам шумные, разброс между блоками 0,02-0,1.
- Мобильные боты ловятся хуже всего: при пороге на recall 70% ловится 81% ботов на web, но только 51% на android и 21% на ios (там их всего 14 в train). По признакам такие боты почти неотличимы от людей.

## Воспроизводимость

- `random_seed` зафиксирован везде, где есть случайность: пять сидов в `03_solution.ipynb` (score усредняется по пяти моделям CatBoost), один сид в `02_experiments.ipynb`.
- `thread_count=4` зафиксирован явно, чтобы результат не зависел от числа ядер машины.
- Версии всех библиотек закреплены в `requirements.txt` (numpy 1.26.4, pandas 2.2.3, scikit-learn 1.5.2, lightgbm 4.5.0, catboost 1.2.10).
- Повторные запуски `03_solution.ipynb`, включая запуск в чистом окружении, собранном только из `requirements.txt`, дают побайтово одинаковый `submission.csv`.
